## 1. 구현해야 할 핵심 알고리즘 5가지 및 연동 규칙

### 1) 분할 정복 (Divide and Conquer) - 실시간 배틀 감지
- **기능**: 서킷 위에서 주행 중인 20대 차량의 GPS (X, Y) 좌표를 기반으로 가장 가까운 두 차량의 쌍을 찾음.
- **알고리즘**: 최근접 점의 쌍(Closest Pair of Points) 알고리즘 사용.
- **적용**: 메인 레이스 루프에서 매 프레임/랩마다 실행되며, 두 차량 간격이 기준치 이하로 좁혀지면 `[BATTLE]` 이벤트를 트리거함.

### 2) 억지 기법 (Brute Force) - DRS 활성화 조건 체크
- **기능**: 배틀 중인 차량이 서킷의 DRS 디텍션 존을 통과할 때 DRS 사용 가능 여부를 판정.
- **알고리즘**: 단순 순차 비교(Brute Force) 및 조건문 체크.
- **적용**: 두 차량의 시간 차가 1초 이하(`gap <= 1.0`)인지 확실하게 전수 검사하여 `DRS Available` 플래그를 업데이트함.

### 3) 동적 계획법 (Dynamic Programming) - 예상 완주 시간 예측
- **기능**: 현재 랩($N$)의 타이어 마모도와 연료 상태를 기준으로, 남은 레이스를 현재 상태로 완주했을 때의 최종 소요 시간을 예측.
- **알고리즘**: 이전 랩의 페이스 저하 누적치를 메모이제이션(Memoization)하여 점화식으로 계산.
- **적용**: 매 랩이 끝나는 시점에 실시간 대시보드 예측 데이터 갱신용으로 호출.

### 4) 분기 한정 (Branch and Bound) - 돌발 상황 시 대안 피트스톱 최적화
- **기능**: 세이프티 카(SC) 발생이나 우천 등 돌발 상황 데이터가 들어왔을 때, 남은 랩 동안의 최적의 타이어 교체 시퀀스를 탐색.
- **알고리즘**: 상태 공간 트리 탐색 시, 현재까지 구한 최적 완주 시간보다 하한선(Bound)이 더 느린 경로는 가지치기(Pruning)하는 분기 한정 기법 사용.
- **적용**: 정해진 이벤트 시점에 작동하여 실제 데이터와 다른 '대안 전술 경로'를 유저에게 제시.

### 5) 공간으로 시간 벌기 (Space for Time Trade-off) - 서킷 데이터 캐싱
- **기능**: 알고리즘 엔진(DP, 분기 한정 등)이 돌 때 메인 레이스 루프가 버벅이지 않도록 기초 데이터를 고속 조회.
- **알고리즘**: 해시맵(HashMap/Dictionary) 또는 2차원 룩업 테이블(Lookup Table) 구조.
- **적용**: 프로그램 시작 시(Initialize) 서킷 섹터별 고정 물리 데이터, 드라이버 가중치를 메모리에 미리 캐싱하고 루프 내에서는 $O(1)$로 참조.

## 2. 기존 코드 보존 및 개발 원칙

- **도메인 유지**: 2021 프랑스 GP의 정적/역사적 데이터 흐름 및 타임라인 스트리밍 구조를 절대 깨뜨리지 말 것.
- **유기적 흐름**: 레이스 재생 중에 알고리즘들이 백그라운드나 루프 안에서 자연스럽게 맞물려 시각화(텍스트/UI)되도록 구현할 것.
- **확장성**: 기존 차량(Vehicle/Driver) 클래스나 데이터 구조를 크게 뒤엎지 말고, 알고리즘 연산을 담당할 별도의 매니저 클래스나 static 함수 형태로 기능을 붙일 것.
